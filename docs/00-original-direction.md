# 工事現場向け スマートウォッチ通知システム 実装ディレクション

## 1. システム全体像（アーキテクチャ）
* **ターゲット端末:** Wear OS スマートウォッチ（SIMなし / 現場Wi-Fi接続 / スマホ非連動の単体運用）
* **通知基盤:** Google Firebase Cloud Messaging (FCM)
* **アプリ配信・更新基盤:** Google Play Console「内部テスト」（審査なし・Wi-Fi経由の自動アップデート）
* **開発環境:** Android Studio / Kotlin (Jetpack Compose for Wear OS)

---

## 2. アプリ側（Wear OS）の仕様と実装方針

スマートウォッチの極小画面で入力ミスを防ぐため、UIは極限までシンプルにし、一度入力した値は端末内に永続化（記憶）させます。

### ① 画面（UI）仕様：`MainActivity.kt`
* **入力項目（2つのみ）:**
1. `site_id`（現場識別子：`Int`）
2. `device_id`（端末番号：`Int`）
* ※キーボード設定を `KeyboardType.Number` に固定し、時計画面には**「数字テンキーのみ」**を表示させる。
* **ボタン:** 「登録 / 更新」ボタン
* **画面表示:** 登録済みの場合は、画面中央に大きく「現場: 101 / 端末: 05（待機中）」のように現在値を表示し、誤操作を防ぐ。

### ② データ保存とToken送信ロジック
1. **ローカル保存:** 入力された `site_id` と `device_id` は、Android標準の `SharedPreferences` に保存する（アプリ再起動やアップデート後も消えないようにする）。
2. **FCMトークン取得:** `FirebaseMessaging.getInstance().token` でToken（`String`）を取得。
3. **APIへのPOST送信:**
* 「登録ボタン押下時」および「アプリ起動時（Token自動更新対策）」に、バックエンドAPIへ以下のJSONをPOSTする。
```json
{
"site_id": 101,
"device_id": 5,
"fcm_token": "fcm_token_string_xxxx..."
}
```

### ③ 通知受信・アラート仕様：`MyFirebaseMessagingService.kt`
工事現場の騒音環境下でも確実に作業員へ気づかせるため、OSの省電力機能を貫通する設定を行う。

* **受信トリガー:** `onMessageReceived` メソッドでAPIからのプッシュ通知をキャッチ。
* **振動（バイブ）:** `Vibrator` クラスを使用し、長めの連続振動（例：1秒振動＋0.5秒休止を5回繰り返す等）を実行。
* **音と表示:** 通知チャンネルの重要度を最大（`IMPORTANCE_HIGH`）に設定し、画面が消えていても強制的に画面を点灯（WakeLock / FullScreenIntent）させ、警告メッセージとアラーム音を鳴らす。

## 3. バックエンド（DB / API）側の仕様

すでにあるDB監視システムに、以下のテーブルと処理を追加します。

1. **DBテーブル定義（例：`watch_devices`）**
* `site_id` (INT) - 複合主キー①
* `device_id` (INT) - 複合主キー②
* `fcm_token` (VARCHAR) - 最新のトークンを上書き保存（UPSERT）
* `updated_at` (TIMESTAMP)
2. **通知送信処理（閾値超過時）**
* 対象の `site_id` と `device_id` から `fcm_token` を検索。
* Firebase Admin SDK（またはHTTP v1 API）を用いて、該当Token宛てに通知ペイロードを送信。
* **【重要】** 送信時は `notification` ではなく **`data` ペイロード（優先度：`high`）** として送信すること（時計がスリープ中でも裏側のプログラムを確実に叩き起こすため）。

## 4. 提供・運用手順（ワークフロー）

### フェーズ1：初期構築（開発者・1回のみ）
1. **Firebase設定:** Firebaseプロジェクトを作成し、`google-services.json` を発行してアプリに組み込む。
2. **Google Play設定:** Google Play Consoleアカウント（25ドル）を作成し、ビルドしたアプリ（`.aab`ファイル）を**「内部テスト」**トラックにアップロード。テスト用Googleアカウントを登録。

### フェーズ2：端末キッティング（現場配布前）
1. スマートウォッチの初期セットアップ（設定用スマホ1台を使い、初期設定完了後にBluetoothを切って独立させる）。
2. ウォッチをWi-Fiに繋ぎ、Google Playストアから自作アプリをインストール。
3. 時計のベルト等に物理シール（例：「現場101 - No.5」）を貼る。
4. アプリを開き、テンキーで `101` と `5` を入力して「登録」をタップ。（これでDBに紐づけ完了）

### フェーズ3：現場運用と機能拡張（日常）
* **現場導入時:** 現場のWi-FiルーターのSSID/パスワードをウォッチに設定するだけ（あるいは全現場でWi-FiのSSID/パスを統一しておけば設定すら不要）。
* **機能拡張（アップデート）:** 開発者がPCでコードを修正し、Google Playの「内部テスト」に新バージョンをアップロードするだけ。現場のウォッチがWi-Fi下で充電されている間に、**全端末が自動的に最新版へアップデート**される。
