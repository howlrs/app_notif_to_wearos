# 提供・運用手順書

作成日: 2026-10-19  
バージョン: 0.4.0（役割別の設定支援・対面確認・回収手順）

元資料: [00-original-direction.md](00-original-direction.md) §4  
対象: 開発者、キッティング担当者、現場管理者

## 1. 概要

本書は、アプリの配信環境を作る「初期構築」、ウォッチを現場へ配る前の「端末キッティング」、配った後の「現場運用と機能拡張」の手順をまとめる。

| フェーズ | 担当 | 頻度 |
| --- | --- | --- |
| フェーズ1: 初期構築 | 開発者 | 1 回のみ |
| フェーズ2: 端末キッティング | キッティング担当者 | 端末 1 台ごと（現場配布前） |
| フェーズ3: 現場運用と機能拡張 | 現場管理者 / 開発者 | 日常 |

表記は他の資料と同じく、無印が原本どおり、「補足」が本書で追加した手順を表す。

### 1.1 導入時の役割と支援（補足）

ウォッチを装着する人に、番号入力、Wi-Fi 設定、更新、障害復旧を必須の仕事として求めない。年齢、学歴、職種から操作可否を決めず、配布時の短い実演で、本人が通知に気付き、内容を理解し、必要な連絡を取れるかを個別に確かめる。本書の手順を採用する前に、現場責任者は現場の安全手順・緊急連絡手段と両立することを確認する。作業の避難・停止・連絡の判断は、既存の現場ルールに従う。

視認、聞き取り、細かい操作、説明の理解をそれぞれ確認する。これらは W3C の[高齢利用者のアクセシビリティ資料](https://www.w3.org/WAI/older-users/)でも扱われる観点であり、本手順では時計の利用場面に応用した。Web 向けの知見だけで時計の使いやすさを判断せず、実際の装着者が普段の眼鏡・手袋・保護具を使う条件で試行する。

| 役割 | 責任と引継ぎ先 |
| --- | --- |
| 導入判断者 | 対象現場、利用目的、運用人数を決め、試行の結果を基に継続可否を判断する。提供者・現場責任者と、導入後の担当範囲を確認する |
| アプリ提供者 | 設定・説明・予備機・保守のうち提供する範囲、支援窓口と対応時間、現在の機能の限界を説明し、保守担当と現場責任者へ引き継ぐ |
| 提供者保守担当 | 端末キッティング、番号・シール・台帳の照合、Wi-Fi・更新・障害復旧、アプリ側の問い合わせを担当する。現場で解決できない事象を受け、現場責任者へ復旧状況を返す |
| 現場責任者 | 配布対象、作業区域、既存の安全手順、連絡先と代替連絡を決める。本人が受信・操作しづらい場合や故障を把握したら、配布担当と保守担当へ引き継ぐ |
| 配布担当 | 当日の台帳照合、対面での装着・テスト通知の実演、充電状態の確認、終業時の回収を行う。設定操作が必要なら本人の横で補助し、結果を台帳へ戻す |
| 装着者 | 装着状態を保ち、通知に気付いた時は既存の現場ルールに従って行動し、読めない・聞こえない・装着できない・故障した時は現場責任者または配布担当へ伝える |

支援窓口は、装着者が覚える番号ではなく、配布担当・現場責任者がその場で連絡できる連絡先として、配布場所と台帳に記す。問い合わせ時はシールの管理番号、現場、症状、発生時刻を渡す。

同じ人が複数の役割を兼ねる場合も、担当者名と不在時の代行者を決める。保守窓口の対応時間外に時計が使えなくなった場合の連絡方法は、現場責任者が配布前に周知する。

## 4. フェーズ3: 現場運用と機能拡張

### 4.1 現場導入時

| No. | 手順 | 出典 |
| --- | --- | --- |
| 1 | 現場の Wi-Fi ルーターの SSID / パスワードをウォッチに設定する。全現場で SSID / パスワードを統一しておけば、この設定も不要になる | 原本 |
| 2 | 補足: 現場の作業範囲で Wi-Fi が届くかを確かめる。ウォッチは SIM を持たないため、Wi-Fi が届かない場所では通知を受け取れない | 補足 |
| 3 | 補足: 現場の全端末へテスト通知を送り、全台が鳴ることを確かめる | 補足 |

テスト通知を送って CLI に `sent` と表示されても、FCM への送信受付を示すだけで、各ウォッチへの到達・表示・内容理解を保証しない。現在、提供済みの管理 UI や各端末の到達を継続監視する機能はない。導入時の全台テストと、配布時の本人ごとの実演で確認する。

補足（現場 Wi-Fi の要件）

| 項目 | 要件 |
| --- | --- |
| 周波数帯 | 2.4GHz を推奨する。5GHz に対応しない機種がある |
| 暗号化方式 | WPA2 / WPA3 パーソナル（パスワード方式） |
| ログイン画面 | ブラウザでのログインが必要な Wi-Fi（キャプティブポータル）は使えない |
| 外向き通信 | TCP 443 と 5228〜5230（FCM）、登録 API への HTTPS を許可する |
| 長時間接続 | ウォッチと FCM の接続は長時間つないだままになる。ルーターが無通信の接続を早く切ると、警告が遅れる。導入時に、しばらく放置してからテスト通知を送り、すぐ届くかを確かめる（[R-21](06-risks-and-open-issues.md#3-技術リスク)） |

### 4.2 配布時の対面確認（補足）

配布担当は、台帳とシールを一台ずつ照合してから本人へ渡す。当日の現場番号の登録、Wi-Fi の接続、アプリ・OS の更新、番号の訂正、エラー復旧は、配布担当または保守担当が事前に済ませるか、その場で本人を補助して行う。本人だけにテンキー入力や設定画面の操作を任せない。

配布時には装着本人へ一台ずつテスト通知を送り、次を実演で確認して台帳へ記録する。テストすることを事前に説明し、時計の画面を消してから送る。送信の瞬間に画面を見るよう促さず、本人が音や振動で気付けるかを確かめる。

1. 装着した本人が、画面を見ていない状態でも振動または音で通知に気付ける。
2. 画面を点けて通知を読み、内容と、事前に教わった行動・連絡先を自分の言葉で説明できる。アプリには連絡先の案内機能はないため、現場の説明や紙の案内を併用する。
3. 「確認」を押して鳴動を止められる。
4. 現場責任者・配布担当への連絡方法と、ウォッチが使えない時の人による代替連絡手段を本人と確認する。

「確認」はその時計の音・振動を止める操作であり、サーバへの ACK、他者への連絡、避難完了や安全の宣言ではない。音・振動では気付けず、画面を見せた時だけ分かる状態は、この確認を通過したと扱わない。読みづらい、聞こえない、振動に気付けない、手袋・保護具・作業姿勢のため操作できない場合は、その場で予備機を試すか、既存の人による連絡手段へ切り替える。本人の属性で判断せず、この実演結果を基にする。

配布時に渡す短い説明文（現場の連絡先に差し替える）:

> 時計が鳴ったら、画面を見て現場の決めた手順に従ってください。「確認」は音を止めるだけです。見えない・聞こえない・操作できない・時計がない時は、現場責任者または配布担当（名前・場所: ______）へ伝えてください。時計の通知を待たず、現場で決めた連絡方法と指示に従ってください。

### 4.3 日常運用（補足）

| タイミング | 作業 |
| --- | --- |
| 朝会後の配布 | 配布担当が貸し出し台帳、物理シール、現場番号を照合して時計を配る。登録が必要な場合は配布担当が事前登録するか、本人の横で「設定変更」から現場番号と端末番号を入力し「登録 / 更新」を押す。前日と同じでも、台帳との照合は行う |
| 配布の直後 | 全台が「（待機中）」で、充電が足り、装着本人の対面確認（§4.2）が済んだことを確かめる。「同じ番号の時計あり　台帳を確認」と出た時計は、配布担当が台帳・シール・番号を見比べて正しい番号へ登録し直す |
| 配布の確認（任意） | 管理者が `cli devices --site <現場番号>` で、その日の台数と番号を台帳と照らし合わせる。番号が重なる行には `duplicate: true` が付く。これは登録情報の照合であり、受信保証ではない |
| 設定変更・端末交換後 | 番号、Wi-Fi、通知許可、音・振動、装着者のいずれかを変えたら、§4.2 の本人ごとのテスト通知を再実施し、台帳を更新する |
| 終業後 | 配布担当が返却・未返却・故障を台帳と照合し、回収した時計を Wi-Fi の届く場所で充電する。自動更新は Wi-Fi 接続中の充電時に行われやすい |

導入初期は、キッティング、配布時の対面確認、問い合わせ、回収・充電に必要な人手と準備時間を、現場ごとに記録する。対面テストの未着件数、作業中の未着申告、代替連絡へ切り替えた件数、復旧までの時間も記録する。未観測の未着は把握できないため、この件数を日中すべての通知の到達率と扱わない。提供者は支援に必要な工数を、導入判断者は現場の運用人数と配布に使える時間を確認して、展開規模を決める。

台数を増やす前に、始業までに本人ごとの確認を終えられるかを試行する。時間が足りない場合は、配布担当の増員や対象人数の調整を検討し、確認を省略することを前提に展開しない。

### 4.4 機能拡張（アップデート）

| No. | 手順 | 出典 |
| --- | --- | --- |
| 1 | 開発者が PC でコードを修正する | 原本 |
| 2 | 補足: `versionCode` を 1 つ上げ、署名付き `.aab` をビルドする | 補足 |
| 3 | Google Play の「内部テスト」に新バージョンをアップロードする | 原本 |
| 4 | 現場のウォッチが Wi-Fi 下で充電されている間に、全端末が自動的に最新版へ更新される | 原本 |
| 5 | 補足: バックエンドの `app_version` 集計で更新の進み具合を確認し、何日も更新されない端末は Play ストアから手動で更新する | 補足 |
| 6 | 補足: 更新後、テスト通知で鳴動を確かめる | 補足 |

補足（更新時の注意）

- 自動更新のタイミングは Play ストアが決めるため、即時ではない。新旧のアプリが混在する期間があるので、登録 API と通知ペイロードは後方互換を保つ（[R-10](06-risks-and-open-issues.md#3-技術リスク)）。
- 通知チャンネルの重要度・音・振動は、作成後にアプリから変更できない。これらを変える時はチャンネル ID の版を上げる（[R-05](06-risks-and-open-issues.md#3-技術リスク)）。
- Google Play の `targetSdk` 要件は毎年更新される。期限までに対応版を出さないと、新しいバージョンをアップロードできなくなる（[R-13](06-risks-and-open-issues.md#3-技術リスク)）。

## 5. 端末の番号変更・交換・紛失（補足）

| 事象 | 手順 |
| --- | --- |
| 端末番号・現場の変更 | 登録済み画面の「設定変更」を長押しし、新しい番号を入力して「登録 / 更新」をタップする。その時計の行が新しい番号に書き換わる。シールと台帳を更新する |
| 番号の打ち間違い（同じ日に同じ番号） | 登録した時計に「同じ番号の時計あり　台帳を確認」と出る。先に登録した時計の行は残り、両方に通知が届く（[D-14](06-risks-and-open-issues.md#2-要決定事項)）。台帳と見比べ、間違えた方が正しい番号で登録し直す |
| 故障による交換 | 代替機をフェーズ2 の手順でキッティングし、同じ番号で登録する。故障機の行は残るため、`cli devices` で故障機の `watch_id` を確かめ、`cli remove --watch <watch_id>` で外す |
| 紛失 | `cli remove --watch <watch_id>` で DB から外す。Google アカウントのデバイス一覧から該当ウォッチを削除する。現場 Wi-Fi のパスワード変更を検討する |
| 返却・長期保管・廃棄 | 時計の行は登録し直すまで残り、保管中も最後の現場の通知が届く（[R-22](06-risks-and-open-issues.md#3-技術リスク)）。長期間使わない時は `cli remove` で外す。廃棄時はウォッチを初期化し、DB から外し、台帳を更新する |

## 6. トラブルシューティング（補足）

| 症状 | 確認すること | 対処 |
| --- | --- | --- |
| 画面に「（未同期）」と出る | Wi-Fi に繋がっているか。現場ネットワークから登録 API に届くか | Wi-Fi を繋ぎ直し、「再試行」をタップする |
| 通知が来ない | ① 画面が「（待機中）」か ② Wi-Fi に繋がっているか ③ DB の行の `updated_at` と `token_invalid_at` ④ 通知の許可 ⑤ おやすみモード ⑥ 現場ネットワークで FCM のポートが開いているか | テスト通知で切り分ける。アプリを開いて再登録させる |
| 設定画面でアプリを強制停止した後に通知が来ない | Android は強制停止されたアプリへ FCM を届けない（[R-12](06-risks-and-open-issues.md#3-技術リスク)） | アプリを一度開く |
| 振動はするが音が鳴らない | 音量、おやすみモード、機種にスピーカーがあるか | 音量を上げ、おやすみモードを切る |
| 警告が鳴っても画面に内容が出ない | Wear OS は通知を手首を上げた時に表示する。全画面の警告画面は自動では開かない（[R-01](06-risks-and-open-issues.md#3-技術リスク)） | 手首を上げるかボタンを押して画面を点ける。通知の「スマートウォッチで開く」で警告画面を開ける |
| 自動更新されない | Play ストアの自動更新設定、Wi-Fi 下で充電しているか、テスターのオプトインが済んでいるか | Play ストアから手動で更新する |
| 入力時に数字テンキーが出ない | 機種のキーボードアプリ | 開発者に連絡する（[R-17](06-risks-and-open-issues.md#3-技術リスク)） |

補足: 上表の Wi-Fi 接続、再登録、更新、設定変更は装着者に単独でさせず、配布担当または保守担当が対応する。現場で直せず、通知を受け取れるか確認できない状態なら、予備機を渡すか、人による既存の連絡手段で本人に伝える。復旧までウォッチだけを連絡手段にしない。
